
# Contributing to Volera

Thank you for your interest in contributing to Volera!

Volera is a macOS customization project developed under the Volera Systems name. Community contributions help improve its stability, performance, design, and overall user experience.

We welcome bug reports, feature suggestions, documentation improvements, and code contributions from anyone interested in helping the project grow.

## Ways to Contribute

There are several ways to contribute to Volera:

- Report bugs, crashes, and unexpected behavior.
- Suggest new features and improvements.
- Improve documentation and instructions.
- Submit code fixes and optimizations.
- Test new features and report compatibility issues.
- Help improve accessibility, performance, and usability.

## Reporting Bugs

Before submitting a bug report, check the existing issues to see whether someone has already reported the same problem.

When reporting a bug, please include:

- A clear description of the problem.
- Steps to reproduce the issue.
- Your macOS version.
- What you expected to happen.
- What actually happened.
- Relevant screenshots, logs, or error messages, if available.

Please remove personal information from screenshots and logs. Never post passwords, authentication tokens, private keys, or other sensitive information.

## Suggesting Features

Feature suggestions are welcome.

When proposing a feature, explain:

- What the feature should do.
- Why it would be useful.
- How it could improve the Volera experience.
- Any potential performance, accessibility, or compatibility considerations.

Volera aims to provide a clean, customizable, and immersive macOS workspace. Suggestions that support this goal are especially welcome.

## Submitting Code Changes

If you want to contribute code, follow these steps:

1. Fork the repository.
2. Create a branch for your changes.
3. Make your changes and keep them focused on a specific issue or improvement.
4. Test your changes before submitting them.
5. Submit a pull request explaining what you changed and why.
6. Link any related issues in your pull request.

Please keep your code readable, follow the existing project structure and conventions, and avoid unrelated changes.

If your contribution changes existing behavior, explain the change clearly and include testing details where possible.

## Reviewing Contributions

All contributions are subject to review.

Submitting a pull request does not guarantee that it will be accepted or merged. Maintainers may request changes, ask for additional testing, or decline a contribution.

The project maintainers make the final decision about which changes are included in the official Volera project.

Please be patient while contributions are reviewed. Review times may vary depending on the project's activity and the complexity of the proposed changes.

## Code Quality

When contributing code, please aim to:

- Write clear and maintainable code.
- Follow the conventions already used in the project.
- Avoid unnecessary dependencies.
- Consider performance and resource usage.
- Test changes on the relevant macOS versions when possible.
- Document significant changes when appropriate.

Do not include code or assets copied from other projects unless their licenses permit the intended use.

## Community Standards

Please be respectful, constructive, and considerate of other contributors.

Harassment, personal attacks, discriminatory behavior, spam, and deliberately disruptive conduct are not acceptable.

Keep discussions focused on improving Volera and helping other contributors.

## Security Issues

Please do not publish passwords, private keys, authentication tokens, or other sensitive information in issues or pull requests.

If you discover a security vulnerability that could expose private data or compromise a user's system, report it privately to the project maintainer when a private reporting method is available.

Until a private reporting method is established, avoid publicly posting exploit details that could put users at risk.

## Questions

If you have questions about contributing, open a GitHub issue and provide enough context for the maintainers to help.

Thank you for helping improve Volera!
